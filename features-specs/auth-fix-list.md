# Auth review fix list

**Verdict: not approved as-is, but this is a good codebase with a few sharp holes, not a messy one.** Tenant isolation holds everywhere — every scoped query takes `workspace_id` explicitly and every handler reads it from the session. Sessions are opaque and hashed, argon2id records its parameters, the CSRF token is an HMAC bound to the session rather than a bare double-submit, and the token bucket is one atomic Lua call. The comments explain *why*, which is rare.

**Status as of 2026-11-10:** **all 18 are fixed.** Findings 4, 6, 7
and 8 were fixed on 2026-11-10 per [auth-fix-plan.md](auth-fix-plan.md); 1, 2, 3
and 5 were already closed when the list was re-checked on 2026-11-09, for the two
structural reasons below. Findings 9 through 18 were fixed on 2026-11-10, in the
order this list suggested, against the full integration suite — real Postgres and
Redis — green before and after.

- `internal/api/members.go` and the whole member-administration feature were **deleted**. Roles went with it — see the schema note at [migrations/00001_auth.sql:28-34](../migrations/00001_auth.sql#L28-L34) and the "no roles" section of `CLAUDE.md`. This resolved findings 2, 3 and 5, and made their line references stale.
- `clientIP` was replaced by [internal/auth/clientip.go](../internal/auth/clientip.go), resolving finding 1.

Line references below have been corrected to the current tree.

## Fixed

**1. ~~Every per-IP rate limit is bypassable with one header.~~ FIXED.** [internal/auth/clientip.go](../internal/auth/clientip.go) reads `X-Forwarded-For` only when the TCP peer is a trusted proxy, and then walks the chain from the right to the first untrusted hop. Private/CGNAT/link-local ranges are trusted by default (unreachable from the public internet, so trusting them spoofs nothing); loopback deliberately is not, so the bypass stays demonstrable locally; public CDN ranges come from `TRUSTED_PROXIES`. The chain is capped at 32 hops, and IPv6 buckets per `/64` so one client handed a prefix cannot mint 2^64 buckets. Covered by [internal/auth/clientip_test.go](../internal/auth/clientip_test.go), including a spoofed-header test (`TestClientIPIgnoresForwardedForFromAnUntrustedPeer`).

**2. ~~`POST /workspace/members` is a free, unmetered account-existence oracle.~~ FIXED by deletion.** The route no longer exists; [internal/api/routes.go](../internal/api/routes.go) mounts only `/me`, `/auth/change-password` and `/auth/logout-all`. The second half of the finding is fixed too: `limitPerUser` meters the authenticated **group** rather than each handler, so an authenticated route cannot be added that forgets to be metered.

**3. ~~Membership is granted without consent.~~ FIXED by deletion.** No membership-granting path exists. The only write to `workspace_members` is in [internal/store/users.go](../internal/store/users.go), inside the `CreateUserWithWorkspace` signup transaction — self-membership, which is consensual by construction. There is no `ON CONFLICT` anywhere in `internal/`. An invite flow is Phase 2, and that is where consent belongs; [internal/store/workspaces.go](../internal/store/workspaces.go) is now read-only (`IsMember`).

**5. ~~Demotion is non-atomic.~~ FIXED by deletion.** No roles, no demotion handler, no `role` column.

**4. ~~Password change is non-atomic.~~ FIXED.** [`ChangePasswordAndRevokeSessions`](../internal/store/users.go) does both writes in one transaction, modelled on `ConsumePasswordResetToken`; [`auth.ChangePassword`](../internal/auth/tokens.go) calls it once. `UpdatePasswordHash` was **deleted** rather than left behind, so the non-atomic path is no longer on offer. Atomicity itself is not unit-tested — proving it needs fault injection between two writes — so the guarantee rests on the single transaction being visible in one function, which is why that function carries the long comment.

**6. ~~The production mailer logs reset links.~~ FIXED.** [`SMTPMailer`](../internal/auth/smtp.go) delivers over STARTTLS (`smtp://`) or implicit TLS (`smtps://`), refuses a non-loopback relay that will not encrypt, and rejects CR/LF in From, To and Subject so a header cannot be injected. `config.Load` now fails closed under `APP_ENV=production` on three settings, each named in the refusal: `SMTP_URL`, `MAIL_FROM`, and a `PUBLIC_BASE_URL` that must be set and must be https. The last two were found while fixing this and are the same bug class — a production deploy would otherwise mail links pointing at the recipient's own machine, from an address every relay rejects. `LogMailer` is now unreachable in production, so the claim in its doc comment is true instead of contradicted. Covered by [config_test.go](../internal/config/config_test.go) and [smtp_test.go](../internal/auth/smtp_test.go). **The SMTP path has no end-to-end test** — a real send is a manual smoke test against whichever provider gets used.

**7. ~~Postgres and Redis published on `0.0.0.0`.~~ FIXED.** Both prefixed with `127.0.0.1:` in [docker-compose.yml](../docker-compose.yml), and so is the throwaway integration Postgres in [scripts/test.sh](../scripts/test.sh), which had the same hole and was not in the original finding. Verified with `docker compose config` (`host_ip: 127.0.0.1`) and a host-side port check. Note: an existing container keeps its old mapping, so `scripts/test.sh db-down` is needed once to pick this up.

**8. ~~Email verification is never enforced.~~ FIXED, and written down.** [`auth.RequireVerifiedEmail`](../internal/auth/middleware.go) gates the `/api` group that feature routes mount inside — empty today, since no feature routes exist until build-order step 3 — and answers 403 `email_not_verified`. Exempt by decision: `/me`, `/auth/logout`, `/auth/logout-all`, `/auth/change-password`. Login still succeeds and still issues a session for an unverified account, so the dashboard can show the "confirm your address" state. The policy is recorded in `CLAUDE.md` and [auth/doc.go](../internal/auth/doc.go), which is what this finding actually asked for. Covered by `TestRequireVerifiedEmail` and [verification_test.go](../internal/api/verification_test.go).

## Fixed in the structural pass

**11. ~~Exported surface with zero callers.~~ FIXED by deletion.** `Service.Store()`, `Service.Config()`, `store.WorkspaceByID`, `Limiter.Allow`, `Decision.Remaining`, `healthBody.Revision` and `var _ *sql.DB` are all gone, along with the `database/sql` and `pgx` imports they were the only users of. `Service.Store()` mattered most: it was an exported bypass of the boundary [auth/doc.go](../internal/auth/doc.go) promises is the only one. `Limiter.Allow` turned out to have one caller after all — [bucket_test.go](../internal/ratelimit/bucket_test.go) — so its eleven call sites moved to `AllowN(..., 1)` in the same wave, rather than the wrapper being kept alive by its own test. `Decision.Remaining` went; the length check on the Lua script's three return values stayed, with a comment saying why, since the script still returns the remaining tokens and that check is what pins the Go side to its contract.

**16. ~~`serverErrorFunc` duplicates `serverErrorf`'s body and logs nothing.~~ FIXED.** The duplicate is deleted. The cause was the callback's shape rather than the body: `auth.ErrorFunc` has no error parameter, so `RequireSession` could not pass on what it knew. There is now an `auth.ServerErrorFunc` that takes the cause, `RequireSession` hands it the error, and [routes.go](../internal/api/routes.go) passes a closure onto `serverErrorf` with `"resolve session"`. A Postgres outage during session resolution now logs the driver error next to the request id.

**15. ~~`Deps` has two routes to Redis.~~ FIXED.** `Deps.Redis` is gone. [`api.Health`](../internal/api/health.go) takes a logger and a variadic list of `api.Check{Name, Ping}`, and [main.go](../cmd/gateway/main.go) writes that list where the clients are opened. The probe loops over it, so adding a cache or a usage buffer for `/v1` is one line next to the client rather than another field threaded through the control plane's handler struct so that one probe can reach it.

**13. ~~Error classification by string match.~~ FIXED.** `strings.Contains(err.Error(), "unknown field")` is gone, and so is the message it forwarded. [`decodeJSON`](../internal/api/routes.go) reads the body once, parses it into `map[string]json.RawMessage` to get the top-level keys, and compares them against `dst`'s json tags itself — answering in its own words and naming the offending field. Two properties had to be preserved rather than tightened: `encoding/json` matches a field name case-insensitively, so this check does too, and a field that is unexported or tagged `json:"-"` is invisible to `encoding/json`, so neither makes a key known. Registering them would have let a body carry that key and have it dropped in silence, which is the outcome rejecting unknown fields exists to prevent. A target that is not a pointer to a struct has no known fields, so every key is unknown and the request is refused: a wiring mistake inside a validator must not fail open. Covered by [decode_test.go](../internal/api/decode_test.go), which the decoder previously had nothing of. The cost is a second parse of a body the cap holds to 64 KiB, affordable for human-rate control-plane endpoints, which is why the comment states that `/v1` must not come through here.

**12. ~~Two handlers re-read rows they already hold.~~ FIXED.** `DefaultWorkspaceID` became [`DefaultWorkspace`](../internal/store/users.go) and returns the row, since the join already reads the workspaces table and the name is therefore free. `handleLogin` assembles its response from the three rows it holds — the user, the workspace, and the `*store.Session` that `CreateSession` was already returning and the handler was discarding — so the `ResolveSession` call and its failure branch are both deleted. That branch was the sharp edge: it answered 500 while the caller was in fact signed in, cookie set and session live. `handleSignup` no longer re-reads the user it just created; [`IssueVerification`](../internal/auth/tokens.go) and `IssuePasswordReset` take the id and the address instead of a `*store.User`. Measured: the `internal/api` suite went from 18.6s to 10.0s.

**9. ~~One policy, three normalizers.~~ FIXED.** [`config.Origins`](../internal/config/config.go) is a named type with one `Allows` method and one `normalizeOrigin`, applied once by `Load`. `corsMiddleware` and [`RequireSameOrigin`](../internal/auth/csrf.go) both call `Allows`, so the copy-paste across the package boundary is gone and so is the drift: an origin carrying a path, a query, a fragment or credentials is now rejected by the only code that decides. A rejected entry is dropped rather than kept beside the error. The second half is fixed too — `ALLOWED_ORIGINS` is required in production, because an empty list makes the same-origin guard refuse every state-changing request a browser sends, so the control plane answers 403 to its own dashboard while the loader says nothing. Outside production an empty list still works, since a request with no Origin header at all passes. `splitList` no longer strips trailing slashes, which it had been applying to CIDR ranges too.

**10. ~~One policy, two layers of defaults.~~ FIXED by deletion.** `auth.Config.withDefaults`, `DefaultSessionTTL` and `DefaultSessionIdleTTL` are deleted. `config` gained `VerificationTTL` and `ResetTTL`, read from `VERIFICATION_TTL` and `RESET_TTL`, defaulting to 24h and 15m and validated positive — so the two values that were reachable only through `withDefaults`, documented as policy and settable by nothing, are configurable. [main.go](../cmd/gateway/main.go) passes all four durations, and `auth.Config` substitutes nothing, which is now stated on the struct: a zero passed in is a zero at runtime. **One tradeoff taken deliberately:** `NewService` does not validate, so the guarantee rests on `config.Load` for the binary and on the test fixture stating every duration. Validating would have meant spelling out four durations in three `auth` unit tests that build a `Service` for cookie and client-IP assertions and never touch a session, which buys less than it costs in noise.

**14. ~~Duplicated token plumbing.~~ FIXED.** `CreateVerificationToken` and `CreatePasswordResetToken` are two-line wrappers over one unexported [`createToken`](../internal/store/tokens.go), in the parameterized form `DeleteStaleTokens` already showed, with the table names as constants in that file rather than a string from a caller. The two `Consume*Token` functions are untouched, for the reason the original finding's own correction gives: they are not interchangeable. The wrappers stay as the typed API, so no caller outside `internal/store` names a table.

**17. ~~`ValidatePassword` runs at both layers with different ordering.~~ FIXED, by moving it where neither layer can skip it.** The rules now live in [`HashPassword`](../internal/auth/password.go), the only door to a stored password: signup, reset and change all pass through it, so a path that forgets to validate cannot exist, and the ordering question disappears because there is one call. `ChangePassword` therefore checks the current password first and judges the new one second, and that is a property of the code rather than of which layer happened to run — a caller who cannot prove the current password is never told which rules their proposed password broke. Handlers translate the refusal through `auth.IsPasswordRejected` instead of pre-checking. Signup keeps one `ValidatePassword` call ahead of its rate-limit spend, so a malformed request does not cost the caller budget; that is a pre-check, not a second enforcement point.

**18. ~~Test coverage is in the wrong places.~~ FIXED.** `integration_test.go` is split along the seams this finding named and deleted. `internal/api` now holds [testenv_test.go](../internal/api/testenv_test.go) (434 lines, the fixture and its helpers), [auth_flow_test.go](../internal/api/auth_flow_test.go) (299), [isolation_test.go](../internal/api/isolation_test.go) (79), [limits_test.go](../internal/api/limits_test.go) (204), alongside the existing `verification_test.go`, `auth_unit_test.go` and the new `decode_test.go`. All 16 tests came across; bodies and doc comments moved unchanged, so the split is a move and not a rewrite. `internal/store` has its own suite for the first time: [store_test.go](../internal/store/store_test.go), [users_test.go](../internal/store/users_test.go) and [tokens_test.go](../internal/store/tokens_test.go), pinning the signup transaction's all-or-nothing behavior, the citext email index, `DefaultWorkspace`, `ChangePasswordAndRevokeSessions`, both `Consume*Token` paths, token expiry and `DeleteStaleTokens`. The replacement test is table-driven over both token kinds, which is what proves finding 14's shared `createToken` kept the two tables behaving identically.

Two things came out of doing it. The store tests **create a database of their own** (`<name>_store`, created on demand), because `internal/api` truncates every table in the database it is handed and `go test ./...` runs packages in parallel: sharing one would reproduce the exact class of intermittent cross-package failure `CLAUDE.md` records for Redis `FLUSHDB`. That needs `CREATE DATABASE` rights on the test server, which the compose and throwaway containers give, and it is now written down in `CLAUDE.md`. And the fixture's doc comment, carried over verbatim, still claimed the tests `FLUSHDB` the Redis instance and guarded a "last-admin guard" that went with roles; both were corrected, since a comment asserting the opposite of the rule that once caused a real intermittent bug is worse than no comment.

**Not proved, and worth saying:** the signup rollback test exercises the failure at the first INSERT, which is where a duplicate address fails. It does not prove a rollback after the workspace insert. Forcing that needs fault injection between two statements, which is the same reason finding 4's atomicity rests on being visible in one function rather than on a test.

**Verified:** 217 assertions pass, 0 skipped, 0 failed, every package `ok` including `internal/store`, which reported "no test files" before.

## Found while fixing, not in the original list

**The integration tests' Postgres port can be unbindable with nothing listening on it.** `TEST_PG_PORT` defaults to 55432, which falls inside a Hyper-V excluded range on some Windows machines (`netsh int ipv4 show excludedportrange protocol=tcp`). Nothing is listening, so `scripts/lib.sh`'s `port_in_use` check cannot see it and docker's refusal to publish is the only signal. Worse, the failed `docker run` left a container in `created`, so every later run took the restart branch and reported a bind error for a port the caller had since stopped asking for. [scripts/test.sh](../scripts/test.sh) now names `TEST_PG_PORT` in the refusal, removes the half-created container, and recreates the container when its published port no longer matches the requested one. This is what `make test-int` was failing on, so it had to be fixed before anything here could be verified.
